# Веб-админка «БытТех»

Панель работает на `/admin` в том же процессе aiohttp, что и `POST /api/requests`. Веб-панель и бот читают одну SQLite-базу из `DATABASE_PATH`. Откройте ветку сайта из связанного PR и используйте её каталог `web/` через `WEB_SITE_ROOT`. Этот каталог содержит текущий дизайн и поля, доступные в редакторе. GitHub Pages остаётся отдельной витриной.

## Windows

В PowerShell из каталога сервера, с Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check web/request-form.js
```

Возьмите переменные из `.env.example` и добавьте нужные значения в ваш `.env.local`. Для проверки пользуйтесь отдельной SQLite-базой и тестовыми реквизитами. Интеграционные тесты используют временные базы и подменяют Telegram. Для запуска самого бота задайте его тестовый токен и идентификаторы администраторов. Укажите абсолютный путь к серверному сайту в `WEB_SITE_ROOT`.

```powershell
.\.venv\Scripts\python.exe -m admin_cli create-owner owner
.\.venv\Scripts\python.exe bot.py
```

CLI запрашивает пароль в терминале и сохраняет его хеш в SQLite. Команда `reset-owner owner` задаёт новый пароль и завершает все прежние веб-сеансы. Чтобы открыть панель в браузере, подключите локальный HTTPS-прокси с доверенным сертификатом к `127.0.0.1:8080`. Прямой HTTP-запрос к админке получает `403`.

## VPS

1. Выделите отдельный каталог релиза и проверьте оба коммита на тестовой базе. Подключите текущие реквизиты, токен бота и `ADMIN_IDS` из защищённого файла настроек.
2. Установите зависимости в виртуальное окружение. Сделайте резервную копию рабочей SQLite-базы по инструкции ниже, затем остановите старый процесс перед переключением версии.
3. Укажите рабочие значения в `.env.local`. Например:

   ```dotenv
   WEB_ENABLED=1
   WEB_HOST=127.0.0.1
   WEB_PORT=8080
   WEB_ALLOWED_ORIGINS=https://your-domain.example
   WEB_TRUSTED_PROXIES=127.0.0.1/32,::1/128
   WEB_SITE_ROOT=/srv/byttech/site/web
   WEB_ADMIN_ENABLED=1
   ```

4. Создайте владельца командой `python -m admin_cli create-owner owner`. Команда использует тот же `DATABASE_PATH`, что и бот. При первом запуске миграция добавляет источник «Телефон» и таблицы панели.
5. Перенесите правила из `deploy/nginx.conf.example` в HTTPS-блок рабочего домена. Прокси должен перезаписывать `X-Forwarded-Proto` и `X-Real-IP`. Оставьте порт приложения доступным только на loopback. Применяйте отключение access-логов на маршрутах панели и ограничьте доступ к файлу базы и копиям на уровне ОС.
6. Запустите один экземпляр `python bot.py` существующим менеджером сервиса. Откройте `https://your-domain.example/admin`, войдите и проверьте список, фильтры и расписание на тестовой заявке. Публикацию контента сначала проверьте на тестовом домене.

## Как работает панель

- «Требуют звонка» — новые заявки старше 24 часов без подтверждённого визита. Переведите заявку в работу после звонка.
- «Новая», «В работе», «Выполнена» и «Отменена» меняются в карточке. «Визит назначен» появляется при подтверждении слота. Дата и время в расписании относятся к Самаре. Пожелание клиента отображается отдельно.
- Архив скрывает заявку из рабочего списка. Подтверждённый визит остаётся в расписании, пока владелец его не отменит. Карточку можно восстановить. Отмена заявки освобождает её слот.
- Редактор хранит черновик отдельно. «Предпросмотр» показывает сохранённый черновик, «Опубликовать черновик» применяет его на серверном сайте. Часы в шапке и подвале относятся к отображаемому графику работы. Правила бронирования задаются в `scheduling.py`.
- Сессии действуют 8 часов. Поиск по контактам отправляется в теле запроса и хранится в сеансе. URL списка содержит только признак поиска и фильтры.

## Резервное копирование и откат

Сделайте защищённый каталог для резервных копий вне веб-каталога и репозиториев. Перед миграцией сохраните снимок базы командой ниже. Подставьте свои пути и создайте каталог назначения заранее. Команда использует SQLite Backup API, проверяет целостность и отказывается перезаписывать существующий файл.

```bash
python -m admin_cli --database /srv/byttech/data/bot.sqlite3 backup /srv/byttech-backup/pre-admin.sqlite3
```

Для остановки веб-доступа к панели установите `WEB_ADMIN_ENABLED=0` и перезапустите процесс. Опубликованный контент при этом остаётся доступен на серверном сайте. Для полного отката остановите процесс, сохраните отдельную копию текущей базы с заявками после обновления, верните предыдущие версии кода и конфигурации, восстановите снимок до миграции и запустите прежний релиз. При наличии новых заявок сначала согласуйте их перенос из сохранённой копии.
