# Подключение обратной связи сайта

## Состояние реализации

Форма и серверный обработчик подготовлены, автоматические проверки выполняются с вымышленными данными и подменой Telegram. В опубликованном сайте адрес API **пустой**, отправка выключена. Это ожидаемое состояние по запросу владельца: нельзя показывать ложный успех или собирать данные до подключения инфраструктуры и заполнения реквизитов.

Публичное место подключения: `docs/lead-config.js`, поле `apiBase`. Допустим только HTTPS origin без пути, query, логина и пароля. Здесь никогда не должно быть токена бота.

## Схема

1. GitHub Pages показывает форму: марка → симптом → имя, телефон, необязательный комментарий и отдельное согласие.
2. Браузер обращается к `/api/config` на сервере в России. Отправка включается только при полной серверной настройке.
3. `/api/leads` проверяет origin, размер тела, поля, версию и факт согласия, ограничение частоты и скрытое поле от спама.
4. Сервер сохраняет заявку и очередь уведомления в SQLite на российском сервере. Повтор того же запроса с тем же UUID не создаёт дубликат. Новый запрос с тем же телефоном обновляет заявку на обратный звонок.
5. Telegram получает случайный номер обращения и ссылку на защищённую карточку. Имя, телефон и комментарий в сообщение Telegram не включаются.
6. Администратор открывает карточку и вводит отдельный логин/пароль. Контакты не передаются в URL и не доступны без авторизации.

Заявки сайта хранятся отдельно от заявок клиентов, прошедших анкету Telegram-бота. Telegram ID у посетителя сайта может не быть. Карточки сайта не появляются в команде `/admin` существующего бота: они открываются из уведомлений на защищённом сервере.

## Что заполнить перед включением

- Разместить API, базу, журналы и резервные копии на подходящей инфраструктуре в России. Проверить весь путь обработки, договоры с обработчиками и применимые требования к хостингу сайта.
- Заполнить `.env.local` на сервере по `web.env.example`: оператор, адрес, email, публичный URL, случайный пароль администратора, `BOT_TOKEN`, `ADMIN_IDS`.
- У каждого получателя Telegram должен быть открыт чат с ботом и выполнен `/start` или `/admin`.
- Проверить юридические документы и заполнить реквизиты; при необходимости заменить шаблоны `docs/privacy.html` и `docs/consent.html`. После изменения текста согласия изменить `CONSENT_VERSION` в `web_leads.py` и видимую версию документов.
- Установить `WEB_DATA_LOCATION_CONFIRMED=ru` только после проверки размещения, а `WEB_FORM_ENABLED=true` — после завершения настройки. Эти флаги сами по себе не доказывают юридическое соответствие.
- В `docs/lead-config.js` задать `apiBase` реального сервера, выполнить `python scripts/build_site_assets.py` и загрузить сайт в GitHub.

## Запуск API

Python 3.12+. Пример из корня checkout:

```sh
python -m venv .venv
.venv/bin/pip install -r requirements-web.txt
# Заполнить .env.local локально на сервере; не вставлять секреты в команды, Git и чат.
.venv/bin/python -m uvicorn web_api:app --host 127.0.0.1 --port 8001 --workers 1 --no-access-log --proxy-headers --forwarded-allow-ips 127.0.0.1
```

Используйте один worker: он обслуживает фоновую очередь уведомлений. Для постоянной работы зарегистрируйте эту команду как сервис операционной системы. API может работать одновременно с polling-процессом бота: он только отправляет уведомления и не запрашивает getUpdates.

Перед API нужен reverse proxy с действующим HTTPS-сертификатом. Пример фрагмента Nginx **внутри уже настроенного HTTPS server**:

```nginx
client_max_body_size 16k;
access_log off;
location / {
    proxy_pass http://127.0.0.1:8001;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
}
```

Не доверяйте произвольному X-Forwarded-For от посетителя. Не открывайте HTTP-порт uvicorn в интернет. Не логируйте тела заявок, Authorization и токены Telegram. Закройте доступ посторонним к `.env.local`, базе, резервным копиям и журналам. База создаётся с правами 0600; шифрование диска, обновления ОС, защита резервных копий и контроль доступа настраиваются на сервере.

`GET /api/config` возвращает `ready: true` только при заполненных реквизитах и настройках. После этого пройдите форму с тестовым номером, проверьте карточку и уведомление. При недоставленном уведомлении очередь повторяет отправку через 30 секунд; уже подтверждённая доставка конкретному администратору повторно не выполняется. При потере ответа Telegram после приёма сообщения редкое повторное уведомление возможно — API Telegram не обеспечивает ключ идемпотентности sendMessage.

## Данные и удаление

Контакты не записываются в браузерное localStorage, URL, аналитику или консоль. Они остаются в памяти открытой формы до успешной отправки. Ошибка сети сохраняет ввод для повтора.

База `data/web-leads.sqlite3` содержит заявки, сведения о согласии и очередь. Срок по умолчанию — 30 дней после последнего обновления; очищается фоновым процессом. Резервные копии должны иметь согласованный оператором срок удаления. Для ручного удаления по подтверждённому обращению:

```sh
.venv/bin/python scripts/manage_web_leads.py --delete-id UUID_ИЗ_КАРТОЧКИ
```

При изменении сроков одновременно обновите код, документы и настройки резервного копирования. Заявка на обратную связь не означает автоматическое заключение договора или подтверждение стоимости ремонта.

## Проверки

```sh
.venv/bin/pip install -r requirements.txt -r requirements-web.txt
.venv/bin/python -m unittest discover -s tests -v
```

Проверить разрешённый Origin, отказ без согласия, неверный телефон, сбой/повтор Telegram, отказ без настройки оператора, защиту карточки, отсутствие дублей и очистку срока хранения. После развёртывания отдельно выполнить реальную сквозную проверку; локальные тесты не подтверждают доставку из ещё не подключённой инфраструктуры.
