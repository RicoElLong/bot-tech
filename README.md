# Бот сервиса ремонта бытовой техники

Python 3.12+, python-telegram-bot, SQLite. Бот работает в личных сообщениях через long polling. Без подключения сайта публичный HTTP-сервер не нужен. Для заявок с сайта предусмотрен HTTP-обработчик на том же процессе; Telegram webhook не используется.

## Запуск

```bash
cd /workspace/bot-tech
python -m venv .venv
.venv/bin/pip install -r requirements.txt
# .env уже есть в репозитории; для личного токена создайте .env.local
cp .env.example .env.local
```

Заполните `.env.local` (или `.env`, если не собираетесь публиковать изменения этого файла):

- `BOT_TOKEN` — токен от @BotFather.
- `ADMIN_IDS` — числовые Telegram ID администраторов через запятую.
- `CONTACTS_TEXT` — телефон, адрес, часы работы сервиса.
- `REVIEWS_TEXT` — текст раздела отзывов; `REVIEWS_URL` — необязательная HTTPS-ссылка.
- `WELCOME_PHOTO` — путь к приветственному JPG/PNG. По умолчанию используется иллюстрация в `assets/welcome.png`; можно заменить своим фото.

```bash
.venv/bin/python bot.py
```

Чтобы узнать ID, временно запустите бота без `ADMIN_IDS`, откройте его и отправьте `/myid`. Затем заполните `ADMIN_IDS` в `.env.local` и перезапустите процесс. Каждый администратор должен сначала открыть бота и нажать `/start`, иначе Telegram не разрешит боту писать ему первым. Не запускайте два процесса с одним токеном.

В облачной среде для работы Telegram требуется разрешить HTTPS-домен `api.telegram.org` в настройках сети. Сохраняйте штатные прокси и проверку TLS. Публичный `.env` содержит только пустые поля секретов и настройки кнопок. Токен храните в игнорируемом `.env.local` или безопасных переменных среды. Не публикуйте заполненный токен в Git.

## Сценарий

1. `/start`: приветственное изображение, запрос собственного контакта кнопкой или номера текстом. Номер проверяется по формату, владение введённым вручную номером не подтверждается.
2. Описание проблемы и модели одним текстовым сообщением (до 2000 символов). Повторный текст заменяет описание. «Далее» сохраняет заявку; описание можно пропустить.
3. Сразу после отправки проблемы — выбор даты и свободного времени кнопками. После записи открывается меню.
4. Меню: «Поломка» обновляет описание существующей заявки и переводит к выбору времени, «Запись» позволяет перенести визит, «Контакты» и «Отзывы» показывают настроенные данные.

`/cancel` возвращает в меню после первой завершённой заявки. `/start` начинает анкету заново; при том же номере телефона обновляется существующая заявка.

Администраторы получают уведомления о `/start`, заявках с телефоном и проблемой, подтверждённых записях. `/admin` показывает статистику, историю входов и заявки с постраничной навигацией. Время отображается по Самаре (UTC+4). Telegram не сообщает боту о простом открытии чата: вход регистрируется при команде `/start`.

Сведения сохраняются в `data/bot.sqlite3`, включая незавершённое описание. Делайте защищённые резервные копии БД и ограничивайте доступ к ней: она содержит персональные данные. При недоставленном уведомлении заявка остаётся в админ-панели. Для заявок из Telegram автоматической очереди повторной доставки нет; для заявок с сайта используется сохраняемая в БД очередь.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты проверяют анкету, сохранность данных после переоткрытия БД, уникальность заявок, занятость времени, перенос записи, защиту от старых кнопок, отказ чужому контакту, формат телефона и доступ к админ-панели. Для проверки Telegram после настройки токена пройдите `/start` с клиентского аккаунта, отправьте телефон и описание, нажмите «Далее», затем проверьте уведомление и `/admin` с аккаунта администратора.

Используйте существующий checkout; отдельный Git worktree для работы в облачной задаче не требуется. После перезапуска облачной среды запускайте процесс бота заново.

Для администраторов в меню команд вместо `/start` показывается `/admin`. Команда `/start` и первоначальная кнопка Telegram «Начать» открывают приветствие с фото и анкету клиента для всех, включая администраторов. Админ-панель открывается только командой `/admin`. Обновление меню применяется при запуске бота.

## Названия кнопок

Меняйте `BUTTON_*` в `.env`, чтобы настроить названия кнопок анкеты, меню и админ-панели. Названия четырёх кнопок основного меню должны различаться; длина каждой кнопки — до 64 символов. После изменения перезапустите бота и откройте нужный раздел заново. Тексты подсказок анкеты подставляют актуальное название кнопки продолжения. Команды `/start` и `/admin` остаются прежними.

Приоритет настроек: переменные процесса, затем `.env.local`, затем `.env`. Личные настройки из `.env.local` не попадут в Git и не будут затёрты обновлением публичного `.env`.

## Одна заявка на контакт

Для каждого нормализованного номера телефона существует одна активная заявка. Российские номера `8XXXXXXXXXX` и `+7XXXXXXXXXX`, пробелы и скобки считаются одним контактом. Повторный ввод проблемы в «Поломке» с последующим нажатием кнопки продолжения заменяет описание в той же заявке. Номер заявки, дата создания и желаемое время записи сохраняются. Пропуск описания при повторном заполнении не стирает прежний текст. Администратору приходит уведомление «Заявка обновлена».

При первом запуске новой версии старые дубли объединяются автоматически: остаётся первый номер заявки, последнее описание и последнее непустое пожелание по записи. Исходные дубли сохраняются в таблице `requests_archive` в той же БД. Перед обновлением рекомендуется сделать резервную копию `data/bot.sqlite3` при остановленном боте.

Номер, введённый текстом, не подтверждается кодом: одинаковый номер с разных Telegram-аккаунтов также обновляет одну заявку. Если требуется проверка владения номером, используйте только отправку собственного контакта или добавьте отдельное подтверждение.

## Запись по времени

После кнопки продолжения в анкете клиент выбирает дату на ближайшие 7 дней, затем один из свободных часов: **08:00, 10:00, 12:00, 14:00, 16:00, 18:00, 20:00, 22:00**. Время Самары (UTC+4). Прошедшие и занятые часы не показываются. Один час в один день рассчитан на одного клиента. При одновременном выборе одного часа второму клиенту предлагается другое время.

Запись сразу сохраняется в SQLite и приходит администратору. При переносе прежний час освобождается только после успешного сохранения нового. История записей хранится в таблице `appointments`, включая прежние варианты после переноса; активная запись показывается в `/admin`. `/cancel` отменяет только текущий выбор, не удаляя ранее сохранённую запись. Данные переживают перезапуск, пока сохраняется файл БД `data/bot.sqlite3`.

Записи из старой версии, введённые свободным текстом, остаются в заявках. Они не занимают часы нового расписания автоматически: их нужно переназначить кнопками, поскольку произвольный текст нельзя однозначно превратить в дату и время.

На Windows пакет `tzdata` устанавливается из `requirements.txt` и нужен для часового пояса Самары.

## Удаление заявки администратором

`/admin` → «Заявки и телефоны» → нужная заявка → «Удалить заявку» → «Да, удалить». Кнопка «Отмена» возвращает к заявке. Проверка прав выполняется как при открытии подтверждения, так и при удалении.

Заявка удаляется из активного списка, занятый час освобождается. Клиент может подать новую заявку через `/start`. Контакт и история входов остаются в базе; история времени сохраняется с отметкой отмены. Повторное нажатие старой кнопки удаления не затрагивает новые заявки.

## Подключение заявок с сайта «Быттех»

В `web/index.html` находится исходный сайт с исправленной формой, в `web/request-form.js` — отправка на `POST /api/requests`. Секреты Telegram в браузер не передаются. Сервер сохраняет заявку и очередь уведомлений одной транзакцией, затем возвращает номер заявки. Успешный экран означает подтверждённое сохранение, а не обещание доставки уведомления в Telegram.

Посетителю сайта Telegram не нужен. Заявка появляется в `/admin` с именем, телефоном, маркой машины, поломкой, комментарием и отметкой «Источник: сайт». В общей статистике учитываются все заявки; счётчик клиентов и история `/start` по-прежнему относятся к пользователям Telegram.

### Обновление и включение

1. Остановите текущий процесс бота и сделайте копию `data/bot.sqlite3` (либо файла из `DATABASE_PATH`). При первом запуске обновляется структура БД, номера заявок и существующие записи по времени сохраняются. Для возврата на старый код нужно восстановить и прежнюю копию БД.
2. Обновите код и установите зависимости: `python -m pip install -r requirements.txt` внутри своего виртуального окружения.
3. Каждый администратор должен открыть бота и нажать `/start`. Его числовой ID можно узнать командой `/myid`; получатели берутся из существующего `ADMIN_IDS`.
4. В существующий `.env.local` добавьте настройки ниже. Сохраните свой `BOT_TOKEN` и `ADMIN_IDS`; не заменяйте заполненный `.env.local` файлом-примером.

```dotenv
WEB_ENABLED=1
WEB_HOST=127.0.0.1
WEB_PORT=8080
WEB_ALLOWED_ORIGINS=https://your-domain.example,https://www.your-domain.example
WEB_TRUSTED_PROXIES=127.0.0.1/32,::1/128
```

Замените адреса на точные адреса своего сайта, без пути и завершающего `/`. Для проверки на компьютере укажите `http://127.0.0.1:8080,http://localhost:8080`. Приём формы с других адресов запрещён. `WEB_ENABLED=0` оставляет обычный режим бота без HTTP-сервера.

5. Запустите один процесс `python bot.py`. Он обслуживает и бота, и сайт. Не запускайте второй экземпляр с тем же токеном. Для работы круглосуточно нужен постоянно работающий хостинг и автозапуск процесса.
6. Настройте существующий HTTPS-хост сайта на проксирование к `127.0.0.1:8080`; пример для Nginx — `deploy/nginx.conf.example`. Заголовок `X-Real-IP` должен перезаписываться реальным IP клиента. Не добавляйте в список доверенных прокси произвольные внешние сети. Включение HTTPS и домен настраиваются у вашего хостинга; код сам их не создаёт.
7. Откройте сайт, оставьте тестовую заявку и проверьте её номер, уведомление каждого администратора и запись в `/admin`. `GET /api/health` проверяет доступность процесса и соединения с БД, но не подтверждает доставку Telegram.

Если сайт уже обслуживается отдельным веб-сервером, разместите там содержимое `web/`, а путь `/api/` на том же домене направьте к процессу бота. Форма использует относительный `/api/requests`. Один статический GitHub Pages не исполняет Python: для обработчика всё равно требуется отдельный постоянно работающий сервер с HTTPS-прокси.

### Повторы, ошибки и уведомления

- Двойной клик и повторная отправка после сетевого сбоя используют один UUID отправки. Сервер возвращает прежний номер, включая после перезапуска; тот же UUID с другими данными получает `409`. После удаления заявки администратором запоздалый повтор не создаёт её заново.
- Сайт не подтверждает владение телефоном. Поэтому новая отправка с тем же номером создаёт отдельную заявку и не изменяет данные или запись пользователя Telegram. Правило одной активной заявки на телефон действует внутри Telegram.
- Для сайта действует ограничение 5 новых заявок с одного IP за 10 минут в текущем процессе, проверка полей, скрытое поле от простых ботов и ограничение размера JSON. Повтор уже принятой отправки не расходует лимит. Ограничение IP сбрасывается при перезапуске; распределённый спам требует защиты на стороне хостинга.
- Если сервер не подтвердил сохранение, форма остаётся на шаге ввода с заполненными данными и показывает ошибку. Токен хранится в `.env.local` или переменных процесса; в HTML и JavaScript его быть не должно.
- Уведомления с сайта сохраняются отдельно для каждого администратора. При ошибке Telegram отправка повторяется с задержкой до 5 минут; `RetryAfter` соблюдается. При включённом приёме сайта очередь продолжается после перезапуска. Удалённые из `ADMIN_IDS` получатели больше не получают старые уведомления.
- При потере ответа Telegram после фактической отправки возможен повтор уведомления с тем же номером заявки: внешняя доставка не гарантирует «ровно один раз». Сама заявка при повторе формы не дублируется.
- База и её резервные копии содержат контактные данные; HTTP-сервер выдаёт только `index.html` и `request-form.js`. Файлы настроек, код бота и БД через сайт не доступны.

Проверки без реальных сообщений Telegram: `python -m unittest discover -s tests -v`. В дополнение к анкете бота проверяются API, миграция, видимость заявок в `/admin`, ограничения доступа по Origin, повторы отправки, лимиты и очередь уведомлений.


## MAX: плавающий виджет и статистика переходов

В `web/index.html` по умолчанию есть плавающая кнопка MAX в правом нижнем углу. Контакт мастера: **+7 (905) 303-15-51**. Все телефонные ссылки на сайте обновлены, мобильная кнопка звонка расположена над MAX.

Личный чат MAX **невозможно открыть по одному номеру телефона** по официально документированному URL. До получения ссылки виджет показывает телефон и кнопки «Скопировать номер», «Открыть MAX» (веб-клиент) и «Позвонить». Поэтому нынешняя кнопка не гарантирует переход сразу к мастеру.

**Включение прямого перехода**: мастер в MAX открывает «Контакты» → «+» → «Пригласить по ссылке», копирует ссылку и передаёт разработчику. В `web/index.html` заменить единственную строку `const MAX_PROFILE_URL = '';` на настоящую ссылку профиля вида `https://max.ru/u/...`. Формат `max.ru/номер` не использовать. Проверить на другом устройстве: должен открываться именно чат мастера. Официальная инструкция: https://help.max.ru/help/contacts/upravlenie_kontaktami/kak_priglasit_v_max_nuzhnogo_cheloveka.

**Место для аналитики**: функция `trackContact(channel, action, placement)` и событие `byttech:contact` в том же HTML. Доступные действия: `max_widget_open` (раскрытие), `max_copy_phone` (копирование), `max_web_open` (открытие MAX без адреса чата), `max_profile_click` (переход на профиль, только после настройки), `phone_click` (звонок). Если внешний скрипт заранее создал `window.dataLayer`, события туда добавляются. Номер клиента, IP, cookie и данные заявки в события не записываются. **Никакая статистика пока не сохраняется и внешние счётчики не подключены**. Для реальной статистики потребуется подключить Яндекс Метрику/свой backend и выполнить требования по персональным данным и согласиям.

Владелец работает как **самозанятый**. Виджет рассчитан на личный профиль MAX и не требует регистрации корпоративного бота. Если решим делать MAX-бота, платформа MAX официально допускает самозанятых резидентов РФ к созданию ботов через партнёрскую площадку.
